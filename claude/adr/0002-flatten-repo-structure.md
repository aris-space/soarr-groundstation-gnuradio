# 0002 — Flatten repo structure

**Status:** Accepted

`gr-sage/` was generated by `gr_modtool newmod`, which always scaffolds a
module inside its own `gr-<name>/` subdirectory — a byproduct of the
tool's default, not a deliberate choice. Flattened its contents to the
repository root (same commit as [0006](0006-rename-sage-to-soarr.md)'s
rename) ahead of writing real documentation, so root-level docs describe
the structure actually used, not an accidental two-layer one.

**Consequence — known wart:** absolute paths embedded in plain-text/JSON
config (`.vscode/settings.json`) and paths baked into artifacts *outside*
version control (the CMake `build/` cache, a shadow-install `.pth` file in
site-packages) aren't caught by grepping the tracked source tree for the
old name — they reference the old *directory name* only, which a
code/identifier grep won't match. A follow-up check after this flatten
found and fixed several of these (a stale `cmake.sourceDirectory`, a
`build/` cache blocking CMake reconfiguration, a stale `.pth` file).
Future restructures of this kind should check absolute paths and
out-of-repo artifacts explicitly, not just grep the tracked tree.
